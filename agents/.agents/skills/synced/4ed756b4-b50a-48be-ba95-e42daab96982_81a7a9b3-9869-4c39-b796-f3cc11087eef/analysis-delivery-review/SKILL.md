# 依頼〜納品の工程別レビュー

**このファイルは入口だけ。原本はNotionにある。**

スキル起動時に、以下の手順で指示を読み込み、その内容に従って処理を実行してください。

1. まず以下のNotionページを `notion-fetch` で読み込んでください（**原本**）：
   https://app.notion.com/p/3dfd48a3c2cb81bb9ab4f547b96bb226

2. 子ページも必要に応じて読む：
   - **AIに投げるプロンプト集**（各工程でClaudeに何をどう頼むか）
     https://app.notion.com/p/3dfd48a3c2cb8117b2a7eb004c4bdb7b
   - **通過ゲート GATE 1〜3（23条件）**：アーティファクト `f4372629-8f1e-4db0-a9f7-efbda224592f`
     ※ **GATE 4（権限付与・送付の直前）は原本ページ側が正**
   - **完全版（384項目・16工程＋横断4）**：https://app.notion.com/p/3e0d48a3c2cb8182b5f8d3144c1773be
     ※ 親ページに**追補16項目の工程対応表**がある。工程の子ページだけ読むと個人情報・セキュリティ項目を見落とすので必ず見る

3. Notionが取得できない場合は、`notion-fetch` の失敗を明示したうえで、下の「原本が読めないときの最小動作」だけを実行する。**推測で工程を捏造しない。**

## いつ使うと効果的か（要約・詳細は原本）

| タイミング | なぜそこか |
|---|---|
| **依頼票を受け取った直後（着手前）** | **最も効く。** GATE 1 は「クエリを1行も書く前」。ここを外すと停止点が全部後ろ倒しになる |
| **自分の手を離れる直前** | レビュー提出前（GATE 2）／依頼者に見せる前（GATE 3）／**権限付与・送付の前（GATE 4）** |
| 引き継いだ案件・初めて担当する案件 | 前任の設計を踏襲してよいかの判定が要る |
| 期限が厳しい案件 | 逆算して「どこを削るか」を先に決められる |
| ターゲット抽出・Rawデータ提供 | 回収不能な操作を含む。GATE 4 と個人情報・セキュリティ項目が効く |

**使わなくてよい場面**：単純な照会（ID既知の参加UU・期間指定だけのレシート数）／クエリの中身の精査＝`bq-query-review`／分析設計・regexの中身＝`receipt-data-analysis`。

## 原本が読めないときの最小動作

原本の全文が取れなくても、次の4つだけは必ず守る。

1. **着手前にタスク種別を判定する**（分析／振り返り基本／振り返り抽出項目あり／Rawデータ抽出／ボリューム算出／ターゲット抽出の6種。併記なら和集合で厳しい方に寄せる）
2. **クエリを1行も書く前に、集計条件マスターの合意を取る**（起案は `bq-query-review` の Mode A に従う）
3. **工程の出口ごとに止まり、「次に進んでよいか」をこちらから聞く**。未充足のまま進むと決めた場合は、条件番号・理由・承認者名を依頼ページに書いてから進む
4. **権限付与・リンク発行・送付の直前で必ず止まる**（宛先の読み上げ確認、親フォルダを含む共有設定の確認、個人情報なら情シスの可否回答）。**ここだけは例外を認めない**
