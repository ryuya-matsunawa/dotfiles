# ONE Brand Design Definition — Summary Slide Edition
## Single-Page Report Summary Reference

## 0. Brand Story

### Product Identity
ONE is WED Inc.'s flagship BtoBtoC platform that transforms receipt data into marketing and analytics value. Users photograph receipts to earn cashback rewards; aggregated purchase data powers enterprise advertising, promotion, and analytics.

### Brand Hierarchy
| Brand | Position | Description |
|-------|----------|-------------|
| **ONE** | Flagship Product | BtoBtoC platform. Receipt cashback (toC) + purchase data analytics (toB) |
| **WED** | Parent Company | Technology and operational foundation. Use only in corporate context |
| **PMN** | B2B Extension | Performance Media Network. Scales ONE's data assets to external media |

### Naming Rules
- "ONE" = always full caps. Font: Brandon Grotesque Black.
- "WED" = parent company context only. Product slides use ONE as subject.
- "PMN" = full name on first mention, abbreviation thereafter.

### "ONE-ness" Expression
Data-first, evidence-driven communication. Express through numbers and facts, not adjectives:
- **Every insight backed by data** — receipts processed, conversion rates, ROI metrics
- **Precision over enthusiasm** — "前年比+32%増" not "大幅に増加"
- **Platform scale visible** — user counts, data volume, partner network size

### Color Pairing Rules (mandatory — check every element)
| Background | Cards/Sections | Text | Accent |
|------------|---------------|------|--------|
| #FFFFFF (White) | #F0F3F6 (Light Gray) | #000000 | #00D184 / #3EE3A6 |
| #F0F3F6 (Light Gray) | #FFFFFF (White) | #000000 | #00D184 / #3EE3A6 |

- **NEVER**: Same color on same color (e.g., #F0F3F6 card on #F0F3F6 BG = invisible = broken layout)
- **NEVER**: #000000 as slide background (black = text and table headers only)
- **Accent greens NEVER for**: Slide backgrounds, large card fills (>25% area), body text, headers

### Chart Color Sequence
1. Primary: #3EE3A6 (ONE Green)
2. Secondary: #00D184 (ONE Dark Green)
3. Tertiary: #8C909B (ONE Dark Gray)
4. Quaternary: #F0F3F6 (ONE Light Gray)

## 2. Typography System

### Font Stack
| Context | Font | Weight | Size | Color |
|---------|------|--------|------|-------|
| Product name "ONE" | Brandon Grotesque | Black | Context-dependent | #000000 / #FFFFFF |
| Numbers (KPI display) | コトノデ (Kotonode) | Bold | 48-72 pt | #00D184 |
| Slide title | Noto Sans JP | Bold | 28-32 pt | #000000 |
| Sub-header | Noto Sans JP | Bold | 20-24 pt | #000000 |
| Body text | Noto Sans JP | Regular | 18-20 pt | #000000 |
| KPI label | Noto Sans JP | Regular | 16 pt | #8C909B |
| Footnote / Source | Noto Sans JP | Regular | 14 pt | #8C909B |

### FORBIDDEN Sizes
10pt, 12pt — these sizes do NOT exist in ONE slides. Body text must be 18pt+.

### Text Density Guidelines (per element)
| Element | Max Words | Rationale |
|---------|-----------|-----------|
| Slide title | 10 words | Conclusion, not topic description |
| Bullet point | 12 words each | One idea per line |
| Table cell | 10 words | Scannable at glance |
| Card body | 50 words | Less text = larger effective font |
| KPI label | 5 words | Concise metric name |

Less text per element forces larger, more readable fonts. All text must be readable from the back of a meeting room.

## 3. Design Tone & Manner

### Core Principles
- **Data-dense**: Consultant-quality information density (McKinsey/BCG level)
- **Flat & clean**: No shadows, no gradients, no 3D effects
- **Sharp & modern**: Clean lines, generous whitespace, grid-based order

### Layout Principles
- One slide = one message (title states the conclusion)
- Left-aligned by default
- Grid-based, orderly layouts with clear hierarchy
- Border-radius: 8 px max on cards and content boxes
- Lines/rules: 1-2 px, #8C909B or #00D184

### Spacing & Overflow Prevention (critical for summary slides)
- Slide edge margins: 40 px+ on ALL sides (top, bottom, left, right)
- Title-to-body gap: 1.5× title height
- Card-to-card gap: ~5% of card width
- Never push content to edges. Always maintain breathing whitespace.
- Content area: Title occupies top 8-15%. Content fills from 15% to **max 88%** of slide height.
- **Bottom safe margin: 12%+ must remain clear.** Content beyond 88% = clipped in presentation = broken slide.
- **If content overflows**: (1) Reduce KPI card count (4→3), (2) Shorten body text, (3) Remove lowest-priority element. NEVER shrink fonts below minimum sizes to fit — remove content instead.
- Summary slides are information-dense by nature. Prioritize ruthless curation over cramming.

### Recommended Layout Patterns for Summary Slides
| Pattern | Best For | Structure |
|---------|----------|-----------|
| **KPI-Row** | Executive summary | Top: 3-4 metric cards (number 48-72pt #00D184, label 16pt #8C909B, card BG #F0F3F6). Bottom: insight paragraph or chart |
| **Statement+Evidence** | Challenge-focused summary | Top: 24-28pt bold conclusion. Bottom: supporting data (chart or KPI cards) |
| **Left-Right 60/40** | Data + insight balance | Left 60%: chart/data table. Right 40%: 2-3 key takeaways. Divider: 2px #8C909B vertical rule |

### Pull Quote / Highlight Box
- **Dark Gray box**: #8C909B background → text #FFFFFF, 22pt. Rounded corners (8px). Use sparingly for key insight. Must be a **standalone block element** (full-width or card-width), never inline within a sentence.

### Inline Highlight Prohibition (critical — export compatibility)
- **NEVER place highlighted text (badge, colored background, special formatting) inline within a sentence or paragraph.** Inline highlights export as images in Google Slides, causing text overlap and misalignment = broken layout.
- **Alternatives**:
  - (A) **Bold + #00D184 color** for emphasizing numbers/terms within body text (no background color)
  - (B) **Standalone KPI card** — pull the number out of the sentence into its own card element
  - (C) **Standalone highlight block** — place the highlighted text in a separate full-width box below/above the paragraph
- Inline badge within running text = broken export = broken layout.

## 4. Charts & Data Visualization

### Core Principle
When quantitative data exists in the source report, CREATE charts directly. Do NOT skip charts or replace them with tables. Charts tell the story faster than tables.

### Chart Types & Color Usage
| Type | Usage | Color |
|------|-------|-------|
| **Bar chart** | Comparisons, rankings, before/after | #3EE3A6 primary, #00D184 secondary |
| **Line chart** | Trends over time | #3EE3A6 line, #8C909B grid |
| **Pie/Donut** | Proportions, share breakdowns | #3EE3A6 primary segment, #00D184 secondary, #8C909B others |
| **Progress bar** | Target vs actual, completion | #00D184 fill on #F0F3F6 background |

### Numeric Context Patterns
- Direction symbols: ▲/▼ for changes (e.g., ▲+32%)
- Inline badges: Small rounded tags in #D7FFF0 for YoY/target comparison
- Source/period: Every chart and KPI must cite source or note "推定" / "社内データ"

### Chart Style
- Minimize grid lines, no 3D effects
- Always include axis labels and insight captions

## 5. Shape-Based Illustrations (Encouraged)

NEVER insert external images (photos, icons, clip art, AI-generated images). Instead, BUILD visual compositions using native slide shapes.

- Combine rectangles, circles, lines, arrows in brand colors
- Use #3EE3A6 / #00D184 for key elements, #8C909B for structure, #F0F3F6 for background shapes

## 6. Voice & Tone

### Writing Rules
- **である調 + 体言止め** (assertive, concise) — NEVER です/ます
- 1 slide = 1 message
- Keep sentences short (max 2 lines per sentence)
- Explicitly state ONE as subject (never omit)
- Every data point must cite source or note "推定" / "社内データ"

### Recommended Content Structure
**結論 → 根拠データ → 示唆/Next Action**

### Title Rules (mandatory)
- Titles MUST state a conclusion or insight
- NEVER use "〜について" or "〜の概要" as titles (= topic labels, not insights = broken title)
- Good: "レシートデータ活用でCVR 2.3倍に改善"
- Bad: "レシートデータの活用について"

## 7. Visual Identity DO / DON'T

### DO
- **White-dominant slides** with #F0F3F6 cards for structure
- **Green accents sparingly** — KPI numbers, chart fills, progress bars, badges
- **Consistent card styling** — same border-radius, same spacing, same typography
- **Data visualization first** — charts over prose, numbers over adjectives
- **Curate ruthlessly** — 1 page = only the most impactful data points

### DON'T
- **Decorative background shapes** — never add circles, blobs, geometric decorations
- **Gradients, shadows, 3D effects** — flat design only
- **Green on large areas** — accent greens are for highlights only
- **Bullet-only slides** — use charts, tables, KPI cards instead
- **External images** — no photos, icons, clip art, AI-generated images (native shapes only)
- **Vague titles** — "〜について" or "〜の概要" = broken title
- **Content overflow** — content beyond 88% slide height = clipped = broken slide
- **Font shrinking to fit** — remove content instead of shrinking below minimums

## 8. AI Generation Prohibitions

### Layout Prohibitions
- Content exceeding 88% of slide height (= clipped = broken slide)
- Constructing slides entirely with bullet points (use charts, tables, KPI cards)
- Shrinking fonts below minimum sizes to fit more content (remove content instead)

### Color Prohibitions
- Accent green (#3EE3A6 / #00D184) as slide background or large card fill
- Same color on same color (e.g., #F0F3F6 on #F0F3F6 = invisible = broken)
- Colors outside the 7-color palette
- Gray body text (body text is always #000000)
- #000000 as slide background (= broken layout)

### Content Prohibitions
- Vague slide titles ("〜について" / "〜の概要" = broken title)
- Hyperbole or chains of abstract modifiers
- Data without source citation
- Data fabrication or alteration (rounding/simplification OK)
- です/ます tone (must be である調)

### Technical Prohibitions
- Inserting external images (photos, icons, clip art, AI-generated files)
- Drop shadows, gradients, 3D effects
- Decorative background shapes (circles, blobs, geometric decorations)
- Font sizes below 14pt. Body text below 18pt.
- Generating cover, section divider, or closing slides (user handles these)
